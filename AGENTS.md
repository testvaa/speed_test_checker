# Speed Test Tray — правила воркспейса

Утилита замера скорости (Go, трей + встроенный дашборд). Лендинг — GitHub Pages,
релизы — через скилл `release-speed-test-tray`.

## Сборка и деплой

- Go не в системном PATH: тулчейн лежит в `D:\tmp\go-toolchain\go\bin`
  (GOROOT=`D:\tmp\go-toolchain\go`).
- `dashboard.html` и `agentorb.js` вшиваются в exe через `go:embed` — любые
  правки UI требуют пересборки exe, иначе пользователь видит старую страницу
  («всё по-старому»).
- Перед сборкой: `go vet ./... && go test ./...`; флаги релизной сборки:
  `go build -trimpath -ldflags "-s -w -H=windowsgui" -o SpeedTestTray.exe .`
- Локальный деплой: Stop-Process → замена через `.new` + `mv` → Start-Process →
  проверить `curl http://127.0.0.1:8787/api/state`.
- Коммиты и теги — только по явной команде пользователя.

## UX-правило: новые функции — предлагать стандартный набор управления

Когда пользователь просит новую функцию, вместе с основной реализацией
предлагать стандартный для таких функций набор действий и состояний —
кратко перечислить и сразу включить очевидное:

- **Действия**: старт/пауза/стоп, перезапуск (rescan/refresh), отмена долгих
  операций; разрушительные действия (удаление, очистка, сброс) — только через
  подтверждение-модалку с честным текстом о последствиях.
- **Состояния**: idle / идёт / пауза / готово / ошибка / остановлено вручную,
  плюс «пустое состояние» (нет данных) и «частичный результат» (после стопа).
- **Индикация**: прогресс, живой таймер, статусная строка, у каждой кнопки —
  своё состояние (видна/скрыта/задизейблена по фазе).
- **Сопутствующее**: локализация RU/EN для всех новых строк, обе темы
  (тёмная/светлая), `prefers-reduced-motion` для анимаций, остановка фоновых
  задач при закрытии/перезапуске приложения.

Если набор неоднозначен — задать один короткий вопрос с вариантами, а не
молчать и не угадывать.
